# إعداد منصة مجتمعي الأكاديمي وربطها بـ Supabase

اسم المنصة وعنوانها لا يتغيران: **مجتمعي الأكاديمي**.

## ما الذي يتيحه هذا الإعداد؟
- تسجيل حساب بالبريد الإلكتروني الشخصي، وليس شرطًا أن يكون جامعيًا.
- اختيار الصفة البحثية وإضافة التخصص والجهة وروابط ORCID أو Google Scholar إن وجدت.
- إنشاء طلب عضوية بحالة «بانتظار المراجعة».
- عدم السماح للحساب غير المعتمد بالوصول إلى بيانات المجتمع.
- صلاحيات قاعدة البيانات تمنع العضو من اعتماد نفسه أو ترقية حسابه إلى مسؤول.
- يستطيع العضو المعتمد تعديل ملفه وعناصره، ولا يستطيع تعديل عناصر الآخرين.
- يستطيع المسؤول مراجعة طلبات العضوية واعتمادها أو رفضها.

## الخطوة الأولى: إنشاء مشروع Supabase
1. افتحي https://supabase.com/dashboard
2. سجّلي الدخول وأنشئي مشروعًا جديدًا باسم مثل `academic-community`.
3. احتفظي بكلمة مرور قاعدة البيانات في مكان آمن، ولا ترسليها لأحد.
4. بعد تجهيز المشروع، افتحي **SQL Editor** ثم **New query**.
5. افتحي ملف `supabase/schema.sql` في هذا المستودع، وانسخي محتواه كاملًا إلى نافذة SQL Editor ثم اضغطي **Run**.

## الخطوة الثانية: إعداد تسجيل البريد
1. من Supabase افتحي **Authentication → Providers → Email**.
2. فعّلي Email provider وتأكيد البريد الإلكتروني.
3. من **Authentication → URL Configuration** أضيفي رابط الموقع:
   `https://mmaahhaa232-cmyk.github.io/academic-community/`
   إلى Site URL و Redirect URLs.
4. للإطلاق العام، أعدّي SMTP مخصصًا موثوقًا من إعدادات Authentication حتى تصل رسائل التحقق باستمرار. لا تعتمدي على خدمة البريد التجريبية للإنتاج.

## الخطوة الثالثة: الحصول على بيانات الربط العامة
من **Project Settings → API** انسخي:
- Project URL
- Publishable key (أو anon public key القديم)

هذه بيانات عامة مخصصة للواجهة، وتعمل بأمان فقط مع سياسات RLS الصحيحة. لا تشاركي أبدًا **service_role** أو **secret key**، ولا تضعيها في الموقع.

## الخطوة الرابعة: تعيين أول مسؤول
بعد إنشاء حسابك وتأكيد البريد، افتحي SQL Editor ونفذي الأمر التالي بعد استبدال البريد ببريد حسابك:

```sql
update public.profiles
set account_role = 'admin', membership_status = 'approved'
where email = 'YOUR_EMAIL@example.com';
```

احتفظي بصلاحية المسؤول لنفسك أو لمن تثقين به فقط. يستطيع المسؤول مراجعة طلبات الأعضاء وتغيير حالة العضوية.

## تنبيه أمني
- لا تنشري مفتاح `service_role` أو كلمة مرور قاعدة البيانات في GitHub أو في كود المتصفح.
- لا تعتمدي طلب العضوية اعتمادًا آليًا على ORCID أو Google Scholar وحدهما؛ الرابط وسيلة مساعدة للتحقق وليس إثباتًا قاطعًا.
- نفّذي مراجعة فعلية للسياسات قبل فتح التسجيل للعامة.
- واجهة الموقع مرتبطة الآن بمشروع Supabase باستخدام Project URL وPublishable key. لن يعمل التسجيل أو المجتمع المشترك قبل تشغيل أحدث نسخة من `supabase/schema.sql` في SQL Editor وإعداد روابط إعادة التوجيه وتأكيد البريد.
- بعد تنفيذ ملف SQL، سجّلي حسابك من الموقع وأكّدي البريد، ثم عيّني حسابك مسؤولًا باستخدام أمر الخطوة الرابعة. لا تفتحي التسجيل العام قبل اختبار حساب عضو عادي وحساب مسؤول.
